# Spec 08 — Testing & Conformance

## Goal

Guarantee the same link opens identically across: native Rust, Node-wasm, browser-wasm —
the core risk of a dual-runtime KDF (any divergence silently bricks links).

## Conformance vectors

A checked-in `vectors.json` (generated by a native Rust `cargo test` — the rlib build from
spec 02 — using **fixed** test secrets/domains, NOT the consumer's):

```jsonc
[
  {
    "name": "token-nopass-exp3600",
    "config": { "secrets": ["<test>"], "domains": ["test.example"], "argon": "minimum", "strict": false },
    "input": { "data": "tok_abc123", "expSecs": 3600, "kind": "token" },
    "deterministic": { "salt": "0011..ff", "nonce": "0011..cc" },   // injected, not random
    "expectEnvelope": "<b64url>",        // exact, byte-for-byte
    "expectOpen": { "data": "tok_abc123", "exp": <fixed-now> }      // time mocked
  }
  // ... password mode, exp=0, kind=binary, epoch>0, each error path
]
```

Rules:

- Every KDF path (HKDF default, Argon2id password), every flag combination, every error code
  has ≥ 1 vector.
- Native Rust generates vectors (byte-exact since salt/nonce are injected and time is mocked);
  Node and browser suites **must reproduce both seal and open byte-exactly**.
- CI regenerates vectors on native and diffs against checked-in file — catches accidental
  format drift in PRs.
- Argon2 vectors use `minimum` profile only (interactive profile verified separately with a
  timing assertion, not byte vectors, since params are compile-time).

## Timing assertions

- Argon2id derive (wasm, `minimum` profile): the **memory-hard path must dominate
  HKDF** by a wide margin (asserted `> HKDF + 10 ms`) and stay within the UX budget
  (`< 1.5 s`). Proves memory-hardness wasn't silently compiled out without pinning a
  brittle absolute floor.
- **Amended 2026-09-26:** the original text asserted `≥ 250 ms`, but the `minimum`
  profile is the OWASP floor (19 MiB, t=2, p=1 — decision D8), which measures
  **~30–60 ms** in wasm. The 250 ms floor was unreachable at those params; the
  assertion now checks the *relative* signal (Argon2 ≫ HKDF) plus the UX ceiling,
  which is what actually catches a compiled-out/stubbed Argon2.

## Fuzzing (cargo fuzz, native)

- Nightly `cargo fuzz` targets live in `fuzz/` (its own workspace root, excluded from
  the stable workspace):
  - `fuzz_targets/decode.rs` — `envelope::decode`: arbitrary bytes → must never panic;
    only `MALFORMED_ENVELOPE` / `UNSUPPORTED_VERSION`.
  - `fuzz_targets/open.rs` — `SealContext::open`: arbitrary strings → error taxonomy or
    clean failure, no panics (sparse registry, so retirement paths are exercised).
  - Corpus seeded from mutated valid envelopes.
- **Stable-toolchain counterpart:** `crates/mosseal-core/tests/fuzz_smoke.rs` runs a
  deterministic, seeded corpus (arbitrary bytes, mutated valid envelopes, hostile
  fragments, every truncation boundary) on the stable toolchain, asserting **no panic**
  and **taxonomy-only errors**. This runs in the `rust-native` CI job; the nightly
  fuzzer explores the same surface without bounds.

## Cross-origin/browser suite (Playwright)

Implemented in `packages/core/e2e/` (run via `npm run test:e2e`). The specs drive the
**real** `@mosseal/core` wrapper against the **real** consumer-compiled wasm in Chromium.

Harness: `e2e/build-harness.mjs` builds two web-target wasm fixtures (lenient + strict —
strict is a compile-time flag, spec 07) with the fixed test secrets, then bundles
`e2e/harness/*.html` with Vite into `e2e/.dist/`. `e2e/serve.mjs` serves it with
`application/wasm`. Cross-host portability and net time are faked with `page.route`:

- seal on `a.test` → open on `b.test` (same whitelist): passes (spec 03 portability).
- open on `c.test` (not whitelisted): `DOMAIN_MISMATCH` (open and seal both gated).
- Net-time mocked via `page.route` for the strict/lenient matrix (spec 07 cases):
  lenient+reachable → opens; lenient+unreachable → system-clock fallback; lenient+expired →
  `EXPIRED`; strict+reachable → opens; strict+unreachable → `STRICT_TIME_UNAVAILABLE`;
  `exp = 0` → opens with the network down (never fetches).
- Network-tab assertion: no `#ms=` fragment ever appears in an outgoing request's
  path/query (instrument via a `request` listener; an ordinary request proves it is live).
- URL detection + `scrubFragmentFromUrl` verified in-browser.

## URL/QR budget test

Max-size v1 payload (255 B data, password) → assert final URL ≤ 512 B and a
`qrcode`/`jsqr` decode roundtrip reproduces the exact URL (Node, no canvas).

## Negative/UX tests

- Wrong password → `BAD_PASSWORD`, no envelope leak in error.
- Tampered envelope byte (flip 1 bit in ciphertext vs header) → `MALFORMED_ENVELOPE` /
  `EPOCH_RETIRED`-family failure, never a panic (see `fuzz_smoke.rs`).
- `EPOCH_RETIRED` for a link sealed under a retired epoch (sparse registry hole).

## CI layout

| Job | Runs | Where |
|---|---|---|
| `rust-native` | fmt, clippy, test (incl. `fuzz_smoke`), vector-gen drift | ubuntu + windows |
| `fuzz-smoke` | nightly `cargo fuzz` 60 s (`decode` + `open`) | ubuntu (nightly) |
| `supply-chain` | `cargo deny --all-features check` + `cargo machete` | ubuntu |
| `coverage` | `cargo llvm-cov --workspace --summary-only` (report-only artifact) | ubuntu |
| `wasm-test` | `wasm-pack test` matrix: `--node` **and** `--chrome --headless` (wasm-bindgen unit tests: secrets parse, `JsError` contract, init failure; the Chromium leg exercises `web_sys::window` hostname detection) | ubuntu (node + chrome) |
| `wasm-node` | conformance wasm, vitest vs vectors, URL/QR budget, Argon2 timing | ubuntu |
| `wasm-browser` | Playwright suite (build harness + chromium) | ubuntu (chromium) |
| `packages` | CLI unit tests, npm pack --dry-run contents | ubuntu |
| `doctor-clean` | `mosseal doctor` + E2E `init`/`build` from the packed tarball | ubuntu (node:22-bookworm) |

## Native coverage

`cargo llvm-cov --workspace --summary-only` is the report of record (report-only; no
hard gate yet). As of 2026-09-26 the native suite (100 tests) measures **91.6%
regions / 84.1% functions / 91.2% lines**. The wasm crate shows 0% natively by
construction — wasm-bindgen code is not host-instrumentable — and is covered instead
by `wasm-pack test --node` plus the Node/browser suites.
